# Local Balance Lab

The Balance Lab is an offline-first workflow for understanding and tuning the gameplay loop. It runs entirely in the browser and does not use Neon, matchmaking, hosted compute, or remote agents.

For hands-on evaluation, **AI Sparring (Endless)** and **AI Sparring (Best of 3)** run human P1 against the selected P2 AI with the configured game rules. Pause and choose **Review Latest Local Round** to reconstruct both players' exact inputs, the AI's one-sided decision trace, accepted actions, exchanges, and gameplay-flow evidence. Exiting review returns to the same paused round.

**Balance Sparring (Local)** is the separate human P1 versus AI P2 playtest mode for candidate rules. Its Pause menu exposes the Balance Lab, and a clean restart applies the staged global tuning, per-character overrides, AI behavior, P2 controller role, and starting situation while retaining the same seed. P1 is explicitly human and has no irrelevant AI-role control. Ordinary sparring, Arcade, Online, and Ranked remain on configured rules. Balance Sparring runs entirely on the local machine.

It is decision support for a human designer, not an optimizer. The tools preserve exact scenarios, expose what the agents requested and what the simulation accepted, and point from a broken loop stage to relevant controls. They do not select a target class win rate or apply an automatic balance fix.

## Run a human playtest

1. Choose **Balance Sparring (Local)**, select both characters and an AI difficulty, and start the match. To test recovery agency directly, pause, open **Balance Lab**, select **Human recovery agency**, then apply the clean restart. This puts human P1 at natural control return inside P2's committed chase instead of asking the human to attack an AI recovery.
2. Play a baseline round, pause, and use **Review Latest Local Round** to inspect the Fight story, exact accepted actions, spacing, exchanges, and P2 decision trace. Open **Human playtest scorecard and decision**, rate only the stages you could actually judge, add baseline notes, then choose **Capture Run As Baseline**. Baseline notes and stage ratings are frozen with that telemetry sample; clear the baseline before editing them again.
3. Change one control or choose one starting situation, then use **Apply + Restart Manually**. The candidate starts on the same seed and the UI confirms that no staged changes remain.
4. Play and review the candidate, then rate its six stages separately and record the comparison conclusion. Each round's actual human and AI inputs are checksum-verified and replayable, but the two human input sequences are naturally independent. The subjective **Clear / Mixed / Blocked** ratings are exported beside telemetry and never alter a rule or automated gate.

## Run a comparison

1. Start the web client with `npm run dev`.
2. Choose **AI vs AI**, select the two characters and an AI difficulty, then start the match. Pause and open **Balance Lab**. Start with a versioned **Gameplay probe** when possible: Open AI mirror, Offense vs passive, Commitment vs defense, Launch-break agency, Pursuit vs escape, Post-clash reset, Post-control agency, Human recovery agency, or Zero-fuel finish. Each probe stages one deterministic situation plus controller roles, states the designer question, and suggests an observation window; it does not score the result. **Launch-break agency** starts defensive P2 already launched with one break available while adaptive P1 is committed to the chase. **Post-control agency** starts P2 at the instant of natural control return inside P1's committed chase. **Human recovery agency** mirrors that state so human P1 can test movement, counter-launch, parry, special, and resource choices against P2 pressure. Use **Starting situation** and **Controller setup** directly for a custom experiment. Passive isolates raw offense, collision, and finish behavior; Defense isolates commitment and parry timing; Escape isolates pursuit, boundary steering, and separation quality. Staged changes are visibly marked pending until **Apply + Restart Manually** creates a clean run, and named probes appear in the live match header, experiment descriptor, and replay source.
   Use **Hide Analysis HUD** when observing animation, spacing, and stage readability without the input rails and aggregate telemetry panel. **Show Analysis HUD** restores the same live evidence without restarting the round.
3. Let the same round run for at least 30-60 seconds. Press `Esc`. Choose **Review Latest Local Round** to inspect the exact observed inputs, checksums, spacing timeline, exchanges, and six-stage loop; exiting review returns to the same paused match. Scenario replays carry their versioned starting-situation identity, so checksum verification and visual reconstruction begin from the same modified state rather than the standard spawn. Open **Balance Lab** when you are ready to capture or compare a tuning sample.
4. Read **Fight story** first. It summarizes concrete exchange outcomes, sustained resets, pressure, and physical overlap, then names the first **Blocked** transition or, when none is blocked, the first **Watch** transition. Its suggested controlled check only stages the matching versioned gameplay probe for the next clean restart; it never changes a rule, restarts the match, or treats the recommendation as a balance verdict. Continue through the **Gameplay loop chain**, **Round flow timeline**, **Movement decisions**, exchange sequence, and diagnostics. The chain follows **Neutral -> Commitment -> Exchange -> Separation -> Chase -> Finish** and labels each stage **Waiting**, **Observed**, **Watch**, or **Blocked** from the current run's flow evidence. It never scores the chain from class win rate. Movement is split into approach, orbit, disengage, and idle on controllable frames, with separate pressure and point-blank ratios for moments where both fighters can act. The exchange panel highlights the longest sustained pressure sequence so the most obvious contact loop is not buried in aggregate counters. Open **AI Decision Inspector** to see each fighter's active controller role, current movement intent, selected action, contextual gates, weighted candidates, and concrete blocker reasons such as helpless, end lag, target helpless, out of range, or no breaks remaining. Scripted dummies identify their role-specific hold, parry, escape, or launch-break decision rather than pretending to use the adaptive policy. Recent intent/action rows open the exact checksum-verified local replay window around that decision. While the playhead is inside that range, **Gameplay Flow Review** recomputes spacing, exchanges, control, and loop stages from only the focused segment instead of diluting it with the full round. Launch-defense reads show whether an incoming pressure-range launch received a pre-emptive or reactive parry, authored guard, or counter-launch; they then separate parry, guard, clash, and counter-hit success from unanswered hits and durable reset conversion. Launch clashes show count, recurrence, each fighter's first accepted action, its delay and pressure context, and rapid launch recommits. Pressure exits show the first accepted action in the new spacing window; a **carried re-entry** means the fighters returned before either AI started a newly accepted action. Use **Review Re-entry** on a brief exit to open the replay immediately before that collapse and inspect the recorded closing speed, both movement intents, boost state, and action-recovery state. Replay Review repeats that causal context on the exchange card and provides a direct seek to the exact re-entry frame, keeping the synchronized decision and input panels on the same moment. **Most constrained control return** selects the clearest Chase failure from both fighters and reports recovery type, return distance, first accepted action, re-launch delay, and durable-reset result. Use **Review Control Return** to inspect that exact checksum-verified window from before control returns through its action, re-launch, or reset aftermath. Accepted combat-start cadence shows whether one repeated action was reduced or merely replaced by another. Detailed aggregate counters are deliberately collapsed below the fight story. Before **Capture Run As Baseline**, open the specific incident you intend to change with **Review Longest Loop**, **Review Control Return**, an exchange review, a re-entry review, or a decision row. The lab preserves that focus window with the baseline instead of reducing the experiment to aggregate round statistics.
5. Use a diagnostic's **Inspect levers** buttons to open and focus relevant controls, or browse the grouped global, AI-flow, and per-character rules directly. In AI-vs-AI, pursuit or commitment evidence links to the relevant AI control before suggesting global physics. Player-specific warnings switch the character editor to the fighter that produced the evidence rather than whichever fighter was selected previously. These links never change a value. The **Local candidate library** can stage a source-controlled experiment with its evidence, exact rule changes, and human question visible beside it. Candidate buttons still only stage a draft: they do not restart, alter the active sample, or change package, Arcade, Online, or Ranked defaults. **Next Run Changes** lists exact active-to-draft values plus starting-situation and controller changes before a restart. Character controls include package-driven natural-recovery reset, dunk pursuit speed/tracking, launch-break recovery/velocity retention, super-boost steering and commitment, special geometry, archetype multipliers, and behavior-specific special payloads. Launch-break startup and active values remain in package data for forward compatibility but are not shown as tuning levers until runtime implements those phases.
6. Use **Discard Staged Changes** to return every pending scope to the current active run without deleting a captured experiment baseline. Use **Save Local Draft** if the experiment should survive a refresh. Use **Download Balance JSON** when the same global, AI-flow, and per-character rules should be exercised by the deterministic local batch runner or shared with another local build. **Import Balance JSON** validates and stages a downloaded versioned draft; imported values remain pending until a clean restart and cannot change an active sample.
7. After capturing at least ten seconds, change one rule and click **Apply + Run [duration] Matched Sample**. The matchup and seed are retained, the score and telemetry reset, both AI controllers restart deterministically, and the HUD shows frame-accurate sample progress. Balance Lab reopens automatically at the baseline's exact frame count. The incident replay pair accepts either zero changes for a repeatability control or exactly one effective global, AI-flow, or character-rule change; it rejects multi-variable candidates. If the candidate finishes earlier, review opens on that finish frame because the changed cadence is evidence rather than a reason to discard the run. Use **Apply + Restart Manually** when you deliberately want an open-ended run.
8. Review the candidate-minus-baseline scorecard. Start with **Gameplay loop before -> after**, which shows each stage's categorical transition without treating `Waiting` as failure or assigning an automatic score. Its active-rule change set names every effective global, AI-flow, and in-match character value changed from the baseline; editor or probe changes made after the run are excluded until a clean restart applies them. Use **Review Baseline Incident** and **Review Candidate Incident** to switch between the two checksum-verified input timelines at the same preserved focus frame and window. The pair requires the same build, seed, loadout, scenario, round identity, controller roles and policies, and exact frame count. Raw event counts are normalized per minute and ratios remain percentage-point deltas. Baseline capture is refused while global, AI, controller-role, character, or starting-situation changes are pending, preventing mixed-rules evidence. Treat every delta as a trade-off: improved separation can still worsen helpless time, finish cadence, or player agency.
9. Open **Human playtest scorecard and decision** to record the hypothesis, separate baseline and candidate notes, and a subjective verdict for each reached loop stage before deciding whether to keep, revert, or iterate. Unrated stages remain explicit. These annotations are human evidence, not automated scoring. **Restore Captured Baseline** stages the exact captured global rules, per-character overrides, AI behavior, starting situation, and controller roles; use **Apply + Restart** afterward to rerun that baseline from frame zero.
10. Click **Export Experiment JSON** after baseline capture to download one `gw.balance-lab-experiment.v6` artifact. It contains the separate human scorecards, exact scenario descriptor and seed, both active global/AI/character rule sets and fingerprints, both raw telemetry samples, both flow timelines and diagnostics, the effective rule-change set, comparison deltas, and explicit scenario/package/duration validity checks. Pending editor or probe values are flagged and excluded because they did not produce the active candidate sample.

### Run a larger local batch comparison

Use the in-game matched sample to decide whether a change is worth screening, then use the deterministic batch runner before promoting it. Both commands run only the local simulator; they do not start the API or contact Neon.

```powershell
npm run ai:batch -- -- --games 12 --max-round-seconds 90 --difficulty cadet,veteran --characters vanguard,duelist --report-name manual-baseline --emit-review-replays
```

Download the staged rules with **Download Balance JSON**, then run the same seeds and pairings with that draft. An absolute path to the downloaded draft is accepted.

```powershell
npm run ai:batch -- -- --games 12 --max-round-seconds 90 --difficulty cadet,veteran --characters vanguard,duelist --draft C:\path\to\candidate.json --compare-report build-artifacts/manual-baseline.json --report-name manual-candidate --emit-review-replays
```

The v15 runner fingerprints the complete sanitized rule snapshot and requires exactly one effective global, character, or AI rule change by default. The comparison report names that path and both values. An unchanged, stale, or contaminated draft fails during preflight before the simulator spends time on the batch. Use `--allow-multi-rule-comparison` only when a compound candidate is intentional; every changed path remains listed and the report is labelled `explicit_multi_variable`. Regenerate older baselines because v14 and earlier reports do not contain the exact snapshot required for this check.

Open `apps/game-web/build-artifacts/manual-candidate.md`. Read **Gameplay Loop Stage Deltas** first: it compares baseline and candidate Blocked, Watch, Observed, and Waiting counts for Neutral, Commitment, Exchange, Separation, Chase, and Finish. A negative flagged delta is evidence that the diagnosed failure happened less often under the controlled sample, not an automatic verdict. Inspect its representative replay and causal metrics before deciding. A candidate that merely replaces a flagged Chase with draws or long unresolved pressure has failed even when the Blocked count falls. Set outcomes remain a later context section and do not affect the stage comparison.
11. Use **Export AI Match Telemetry** when you only need the current round's complete event stream. The `gw.ai-match-telemetry-export.v8` export includes match, round, and round-index seeds; active and pending global, AI-behavior, controller-role, and character-rule fingerprints; exact override objects; the versioned starting situation and `gw.ai-controller-roles.v1` setup; the `gw.ai-decision-telemetry.v3` role/intent/action/blocker trace; and the distilled flow model with its full exchange review and causal pressure-re-entry context.

Training mode supports the same workflow and its own telemetry export. Balance Lab is deliberately unavailable for live online matches, so local edits cannot contaminate ranked determinism.

## Test the launch-break agency candidate

1. Start **Local -> AI vs AI** with Vanguard and Duelist, pause, and open **Balance Lab**.
2. Select **Launch-break agency (20s)**. This stages the `launch_break_decision` situation with P1 Adaptive and P2 Defense Dummy.
3. Choose **Stage Launch-break agency V1**. Confirm **Next Run Changes** contains only Vanguard launch-break recovery `18 -> 6`, Duelist launch-break recovery `28 -> 10`, the launch-break decision situation, and the defensive P2 role.
4. Choose **Apply + Restart Manually**. The match header must show **Probe: Launch-break agency**. Reopening the lab must show Vanguard recovery `6`, Duelist recovery `10`, and no pending changes.
5. Watch whether the defender gets one readable choice after spending the break: disengage, counter-launch, parry, special, or resource movement. Reject the candidate if it simply creates an immediate free counter-rush, preserves constant shared pressure, or removes finish progression.

This is a two-rule, human-review candidate, not a live balance update. A current-schema mirrored screen ran 12 Veteran sets in each Vanguard/Duelist direction on identical seeds. Compared with the 50-round baseline, the 48-round candidate moved Chase from `10 Blocked / 40 Watch / 0 Observed` to `2 Blocked / 44 Watch / 2 Observed`, Commitment from `4 / 42 / 4` to `6 / 30 / 12`, and Separation from `0 / 10 / 40` to `0 / 8 / 40`, with no timeouts. The returning fighter gained roughly `0.56-1.19s` of average control window depending on side, but shared action-ready time fell `0.10` points, shared pressure rose `0.60` points, sustained shared decision windows fell `0.04` per round, and exchange-reset conversion fell `3.10` points. A moderate `10/14`-frame variant retained eight Blocked Chase samples and worsened Separation, so it was rejected. The aggressive `6/10` candidate remains local-only until direct human play confirms that the extra agency is visible and tactically useful.

## Review a real ranked match locally

Developer builds retain only the latest server-verified ranked proof on that device. Open **Replays -> Review Last Ranked Match** to verify the receipt again and reconstruct every round from authoritative inputs. This path does not query Neon or run hosted analysis. Production builds do not retain this local proof or show the entry unless debug tools are explicitly enabled.

The replay opens with a frame-synchronized **AI Decision -> Input Request -> Accepted Start -> Outcome** chain for both fighters. It keeps the exact sparse decision event, controller role, movement intent, tactical selection and reason, weighted or blocked candidates, emitted controls, simulator-accepted starts, and matching move resolution together at the selected frame. If the payload is human-authored or predates decision tracing, the panel explicitly reports that no AI trace exists while retaining its input, accepted-start, frame-data, event, and flow review. The flow panel uses the same analysis as Balance Lab and keeps round boundaries independent. It leads with the same deterministic **Fight story**, but its suggested controlled check is read-only in Replay Review and cannot stage or change a rule. The six-stage gameplay loop chain follows, then shared movement-control and action-ready time, steerable contact/pressure, sustained shared decision windows, physical-contact episodes, long/mid/pressure/point-blank spacing over time, launch-clash count/rate/recurrence and post-clash choices, spacing resets, pressure duration, exchange resolution, control-return-to-relaunch timing, accepted combat-start cadence, accepted kit coverage, action entropy, dominant-action share, repeat streaks, and accepted starts over requests. Select a contact episode or exchange to seek directly to its opening frame, then inspect both players' inputs and move phases.

Use this to compare the AI's intended decisions with simulator-accepted actions. A requested action that never starts is a controller/state-recognition problem; a started action that produces no spacing or outcome is a mechanics problem. Do not infer either from the round winner alone.

## Review a flagged AI batch sequence locally

Run `npm run ai:flow-review` from the repository root while the local Vite development server is running. Open **Replays**; the development-only **Local AI Flow Cases** controls load the generated catalog automatically. Activate the **Case** row to cycle through flagged Neutral, Commitment, Exchange, Separation, Chase, Finish, worst-exchange, and timeout cases, then choose **Open Selected AI Flow Case**. Blocked cases appear first, followed by Watch cases and representative sequences. The status panel shows the diagnostic evidence and relevant tuning controls before opening the replay. Chase cases name the affected fighter and open 0.5 seconds before that round's most constrained control return, continuing through its first accepted action, re-launch or two-second reset window, and a short aftermath. Their catalog summary states the return kind and time, first action and delay, re-launch delay, and whether a durable reset occurred. Finish cases select a checksum-verified launch hit against an empty target where no accepted dunk starts before control returns, the attacker recommits, the round ends, or the sample ends. Completed opportunities are preferred over a truncated sample tail, then the narrowest window and latest exact tie are selected deterministically. The replay opens 0.5 seconds before the launch and retains a short aftermath; its catalog summary names the attacker and target, launch time, target and separation speed, and the event that closed the conversion window. Other flagged stages retain their evidence tail, representative exchange, or timeout tail. The viewer rejects malformed files and frame-checksum drift and reconstructs the exact draft tuning and character overrides used by the batch.

Use `npm run ai:alpha-flow-review` when investigating the exact 12-set, 90-second scenarios and thresholds used by the online-alpha AI gate. Use the faster `npm run ai:flow-review` while iterating. Both commands run locally and overwrite the same development catalog; neither contacts the API, Neon, or any hosted analysis service.

The generated Markdown and JSON begin with a cross-matchup **Designer Brief**. Start with its primary bottleneck and top three deterministic representatives before reading set outcomes or the full metric tables. Its ordering uses only Blocked, Watch, Observed, and Waiting stage evidence; class wins are deliberately excluded. Repeated AI, global, and character lever counts tell you where the evidence points without changing any value automatically.

The catalog bridge reads only `build-artifacts/local-flow-review.json` and its declared replay files, exists only in the Vite development server, and is absent from production builds and previews. It does not use the API, Neon, or another hosted service. **Open Local Replay JSON** remains available for custom report names or batches run manually with `--emit-review-replays`.

Use the representative kinds for different questions:

- **loop-neutral / commitment / exchange / separation / chase / finish**: inspect one deterministic Watch or Blocked round together with its recorded reason and linked tuning families.

- **worst unresolved**: inspect why accepted pressure produced no clash, hit, defense, resolved special, or finish.
- **worst brief exit**: inspect why apparent separation failed to become a sustained neutral window.
- **worst contact**: inspect the round with the strongest physical-contact occupancy and whether collision, pursuit, or recovery caused it.
- **worst timeout**: inspect the final twelve seconds of the timed-out round with the strongest pressure/contact signature and identify which reset, chase, or finish transition failed to complete.

This is the bridge between aggregate evidence and visual judgment. Treat win totals as context for AI or kit asymmetry, not as the tuning objective. The primary loop remains neutral, commitment, exchange, separation, chase, and finish.

## Read the round flow timeline

The **Gameplay loop chain** is the first-pass narrative. **Waiting** means that stage has not produced enough evidence, **Observed** means the stage occurred without a known gross pathology, **Watch** means the evidence deserves inspection, and **Blocked** means the current sample failed to progress through that stage reliably. These labels are investigation aids, not a fun score or matchup verdict. Watch and Blocked stages expose up to three high-priority **Inspect levers** links; the detailed diagnostics below retain the full control list.

The timeline aligns spacing and accepted combat events against the same match clock. Its colored track shows long, mid, pressure, and point-blank occupancy; P1 event markers sit above the track and P2 markers sit below it. Hover or focus a marker for its exact time and event. The recent-event row keeps the last ten important moments readable without requiring the full telemetry export.

The **Exchange review** directly below the timeline groups every continuous pressure phase into an inspectable gameplay-loop unit. Each row reports the accepted opener, time spent under pressure, concrete outcomes such as clashes, hits, parries, launch breaks, resolved specials, and finishes, plus the spacing band and neutral window that followed. It also identifies the first simulation-accepted action after the exit and its delay. In AI-vs-AI, choose **Review** on a row to open the checksum-verified round 0.75 seconds before that exchange; exiting replay returns to the same paused match. A green reset means the fighters remained outside pressure for at least 0.75 seconds. A brief exit means they crossed a distance threshold but immediately re-engaged; a carried re-entry means that happened before a fresh accepted action. Current telemetry labels its cause as held boost, held approach, action-recovery momentum, uncontrolled launch momentum, residual closing velocity, or unknown legacy context. Event sequence decides the boundary, so an action accepted later on the same frame as pressure re-entry is not falsely credited as its cause. An unresolved row means the game recorded pressure without a meaningful combat outcome. Only the latest twelve exchanges are rendered to keep the pause menu readable; every exchange is retained in the exported `flow.exchanges` array alongside the raw telemetry used to derive it.

The **Movement decisions** bars classify input relative to the opponent, not screen direction. Approach means input has a substantial component toward the opponent; disengage means away; orbit is mostly tangential; idle means no meaningful movement input. The pressure and point-blank A/D readouts isolate close-range policy. A high point-blank approach share with almost no disengagement is controller evidence first, while high contact despite varied disengagement points more strongly toward collision response, pursuit, or recovery mechanics.

Use it to answer concrete loop questions before changing numbers:

- Does an approach produce a clash, whiff, defensive response, or launch, and does that exchange create visible separation?
- After a clash, does each fighter preserve the separation, orbit, defend, or immediately boost and launch back into the same exchange?
- After a launch hit, does the defender delay or immediately spend a launch break, and does either choice create a repositioning window?
- Do specials, parries, and super boosts change spacing, or are they accepted inputs that leave both fighters at contact range?
- Does a launch create a credible chase and dunk attempt, or does the round return to point-blank pressure without advancing the win condition?
- Are there sustained mid/long neutral windows between pressure sequences, or only momentary crossings while the fighters remain locked together?
- Which specific exchanges are unresolved or end in a brief exit, and what accepted opener led into each one?

The per-player launch-pressure readout reports received launch hits and helpless seconds per received hit. Read those values independently: a high helpless share can come from repeated launch conversions even when each recovery window is reasonable, or from an excessive recovery window after only a few hits. The launch-break readout reports uses and average reaction time. The zero-fuel finish funnel reports launch hits against an already empty target, accepted dunk starts against an empty target, and round-winning dunks. Read those stages separately: a missing opportunity, a missing AI commitment, and a failed mechanical conversion require different fixes.

The **Accepted combat starts / min** row is a cadence measure for launch, special, dunk, parry, and launch break. A lower value is not automatically healthier. Read it beside the per-action starts/requests, dominant-action share, repeat streak, pressure occupancy, and launch-clash rate. If launch cadence falls while special cadence rises and pressure does not release, the same interaction loop has only changed buttons.

Do not tune toward a desired AI class win percentage from this view. First improve the sequence of neutral, commitment, exchange, separation, chase, and finish; use win percentage later to identify AI or kit asymmetry that deserves human playtesting.

## What the diagnostics mean

- **Early sample: keep observing**: no gross issue has fired yet, but the unfinished run is shorter than 30 seconds. Continue to 30 seconds or a round end before interpreting the absence of a warning as evidence about the full neutral-to-finish loop. A ten-second run remains valid for quick matched experiments; it is not labelled healthy.
- **Point-blank lock**: more than 55% of a meaningful sample is spent inside the broader 12-unit close-range band. Look at clash separation, whiff recovery, retreat incentives, and defensive pushback.
- **Launch-clash loop**: at least four launch clashes occur at six or more per minute; six clashes at ten or more per minute is critical. The Exchange stage is downgraded because repeated cancellation is not a healthy resolution by itself. Inspect clash grace, separation/recoil, recurrence within one second, each fighter's first accepted post-clash action and delay, and the spacing that follows. A longer delay is not automatically healthier if contact remains high or rounds stop finishing.
- **Pressure never releases**: more than 82% of the sample stays within the pressure band. The game may lack a readable neutral reset.
- **Contact lock**: at least 20% of the sample is within combined fighter radii plus a 0.75-unit tolerance. This isolates sustained body contact from the broader 12-unit point-blank band; 35% is critical.
- **No shared decision window**: both fighters were action-ready for at least five seconds, at least 65% of that time remained in pressure, and no outside-pressure episode lasted 0.75 seconds. This rejects false neutral created only by helpless travel, forced recovery, end lag, or an ongoing commitment.
- **Commitments saturate shared pressure**: both fighters could steer for at least five seconds and recorded at least eight accepted tactical starts, but at least 75% of shared-control time remained in pressure and both were simultaneously action-ready for no more than 30% of it. The diagnostic reports steerable contact, pressure, and accepted cadence; inspect AI decisions and per-character frame data rather than treating collision impulse as the only cause. Ten percent action-ready share with at least 85% steerable pressure is critical.
- **Neutral reset drought**: one uninterrupted point-blank/pressure sequence lasts at least 12 seconds. Tune clash separation, defensive displacement, commitment, and retreat incentives.
- **Point-blank pursuit loop**: a fighter has at least three seconds of point-blank evidence where both fighters can act, approaches on at least 32% of those frames, and disengages on no more than 8%. Inspect AI spacing and retreat policy before compensating with stronger collision separation or weaker attacks.
- **Failed reset**: at least three clashes, parries, or launch breaks occurred but fewer than 35% created 0.75 seconds outside the pressure band within two seconds. Read the separate clash, parry, and launch-break conversion values before changing a shared rule.
- **Immediate re-engagement loop**: at least half of six or more pressure phases leave close range for less than 0.75 seconds. The diagnostic reports how many brief exits resumed without a newly accepted action, shows the causal mix, and names the dominant investigation path. Held approach or boost points first to AI pursuit/commitment policy; action-recovery momentum points to recovery control; uncontrolled momentum points to helpless release/damping; residual closing velocity points to damping/separation. Unknown means the source stream predates the causal context. A low carried share with repeated newly accepted actions points first to decision policy. Do not count either transition as neutral.
- **Pressure without outcomes**: at least 30% of six or more pressure phases produce no clash, hit, parry, launch break, resolved special, or finish and average at least 1.5 seconds. Inspect accepted inputs and AI state transitions before increasing move power.
- **Automatic launch-break spending**: a fighter used at least three launch breaks with an average reaction below 0.12 seconds. Treat this as an AI state-transition problem before changing launch power, helpless duration, or the escape resource itself.
- **Helpless lock**: either fighter spends at least 45% of a meaningful sample without control. Compare received-hit frequency with helpless seconds per hit before changing anything. Frequent short windows point first to the attacker's launch conversion and the defender's movement or launch-break policy; long individual windows also expose the global launch-release and damping controls. Player-targeted links open the corresponding fighter's controls directly.
- **Immediate re-launch loop**: after at least three control returns, a fighter is launched again within one second after at least half of them. The panel reports the average control window, first accepted action mix and delay, whether that action occurred before re-launch, sustained reset measured from the actual control-return moment, and sustained reset after the first action. This separates repeated re-engagement, post-return movement, and action choice from an individually long helpless timer.
- **Post-control reset failure**: at least three pressure-range control returns occurred but fewer than 35% produced a sustained reset. This remains a Chase failure even when re-launch takes longer than one second; merely delaying the same tracked re-engagement is not healthier neutral.
- **Defensive read gap**: at least four pressure-range launch commitments were observed, fewer than 35% received a parry, authored guard, or counter-launch answer, and at least 40% became unanswered hits. Inspect AI threat recognition and authored defensive timing before changing launch power. The launch-defense rows separately show read coverage, each answer type, success by tool, and success-to-reset conversion.
- **Ineffective Guard usage**: at least three authored Guards were associated with incoming pressure launches, but fewer than 25% stopped the launch. Inspect when the controller spends Guard and whether authored startup leaves a valid response window before changing Guard strength or global launch power.
- **Rejected-input churn**: fewer than 45% of an agent's combat presses become simulation-accepted action starts. The diagnostic names the player and action with the largest rejected-request count. The `L / S / D / P / B` rows show simulator-observed accepted starts over distinct requests for launch, special, dunk, parry, and launch break, including starts consumed later in the same frame. This separates controller bugs from weak moves before changing move strength.
- **Narrow tactical loop**: a fighter has used fewer than three accepted tactical action types after 20 seconds. Fix AI recognition or mechanical usefulness before buffing an unused action blindly.
- **Repetitive tactical loop**: one action represents at least 72% of accepted tactical starts, or the same accepted action repeats six times without another tactical action. Use dominant-action share, normalized action entropy, and repeat streak to identify the state transition that is missing.
- **Zero-fuel stall**: a fighter spends at least 30% of the sample empty without a dunk connecting. Check chase behavior, launch release speed, helpless duration, and dunk startup/range.
- **Launches do not become finishes**: at least three launch hits occur without one accepted dunk start. Inspect the launch-to-chase-to-dunk pipeline rather than raw damage or win rate.
- **Round finish risk**: no dunk has connected after 45 seconds. Activity is not progressing toward the win condition.

Diagnostics link to the relevant AI behavior, global controls, and, when the event identifies one, the specific fighter's move family. The link only expands and focuses an input; it deliberately does not prescribe a direction or apply an automatic fix. Change one lever at a time and compare the same seed.

These are local investigation heuristics, not balance claims. A clean panel means no known gross flow pathology was detected; it does not prove that a matchup is fair or fun. Class win percentage is reported as context for AI and kit behavior, but the primary target at this stage is a readable loop with shared decision windows, varied accepted actions, managed fuel, and credible finish attempts.

## Tuning scope

The global editor groups `GameTuning` into **Pace and movement**, **Launch and control**, **Spacing and resets**, and **Finish and recovery**. It covers movement acceleration and damping, boost and super-boost behavior, action-recovery control authority, launch power and helpless windows, chain timing, directional influence, body separation, defensive resets, clash grace, and dunk recovery. The per-character editor stages full numeric package overrides without mutating `apps/game-web/content/characters`. It covers archetype multipliers, attack/defense frames, fuel costs, dunk pursuit, and behavior-specific block, dash, command-grab, or projectile values. Special behavior identity remains package-owned and cannot be changed in the editor.

Local AI-vs-AI also exposes **AI flow behavior**. These controls change what the evaluator chooses, not the simulator's combat rules:

- **Engagement Distance Scale** changes the distance at which the current difficulty profile considers offensive commitments.
- **Neutral Inward Drive Scale** transfers reduced long-, mid-, and close-neutral approach input into orbit input. It changes pursuit shape without slowing character movement or changing move data.
- **Neutral Boost Distance Offset** postpones ordinary free auto-lock boost by an exact distance. It does not alter super boost, finish chase, or low-fuel chase behavior.
- **Pressure-Exit Hold Frames / Distance** creates a deterministic spacing-preservation window after leaving pressure.
- **Commitment Observe / Press / Reset Frames** stages complementary response and initiative roles around a shared post-event reset. Both fighters derive the same initiative owner from the round seed. Control returns and clashes may start a shared reset; its timer advances only while both fighters are action-ready, including neither fighter being in parry. Offensive whiffs transfer initiative directly without forcing another bilateral pause. The phases are bounded and expire to ordinary behavior; all three default to zero and are experimental.
- **Post-Clash / Post-Recovery Spacing Frames** isolates whether immediate recommit after those events is causing the loop.
- **Post-Control Steering Frames** applies retreat/orbit movement after a close control return without adding the older spacing policy's reaction lock. Valid launches, parries, Guards, and other counters remain available; an auto-target movement dash is withheld only while it would directly cancel the attempted reset.
- **Post-Event Retreat Chance / Recovery Escape Super Boost Chance** controls seeded defensive posture choices without consuming the ordinary AI RNG stream.
- **Post-Control Disadvantage Defense Frames** opens a local decision window only when control returns at close range and the fighter's authored launch startup is slower than the opponent's. Ordinary launch choice is withheld during the window.
- **Post-Control Defensive Special Chance** can select an available block-guard special before a threat during that window.
- **Post-Control Threat Parry Chance** rolls at most once and only after a nearby launch or incoming projectile that parry can actually stop.
- **Committed Launch Guard Chance** rolls at most once when a nearby opponent begins a launch and only if the authored block special can become active before that launch. It does not react to dunk or generic special commitments.
- **Reaction Delay, Error Rate, and Risk Appetite** adjust the effective difficulty profile for the experiment.
- **Launch, Special, Dunk, Parry, and Launch-Break weights** adjust decision mix without changing move strength, cost, range, or frame data.
- **Finish Pursuit Reach Scale** changes how much package-authored dunk-startup pursuit the AI may count only when chasing a helpless zero-fuel target. It does not alter ordinary dunk range, movement, or hitboxes.

Every scale defaults to `1`; offsets, spacing, steering and commitment windows, escape chance, all three post-control defense controls, and committed-launch Guard chance default to `0`. That neutral configuration preserves the shipped input policy under the current controller revision. AI controls are available only in local AI-vs-AI, are frozen at a clean restart, and never alter Training, Arcade, Versus, Online, or Ranked.

The flow-specific global controls are:

- **Launch Release Speed Ratio**: ends helpless state when drift falls below this fraction of that character's normal boost speed. Higher values return control sooner.
- **Startup Clash Grace**: treats an opponent whose launch is this close to becoming active as a simultaneous launch. Zero preserves the existing active-vs-active rule.
- **Clash Separation Padding / Recoil Scale**: independently controls the immediate distance and outward velocity created by a simultaneous launch clash. These controls do not change a successful launch's power.
- **Action Recovery Control**: scales how strongly ordinary movement, held boost, and ongoing super-boost steering can override momentum while move end lag is active. `1` preserves full current control; lower values make launch, dunk, special, and parry recovery more committal without changing startup, hit power, or recovery duration.
- **Body Separation Padding / Impulse**: controls neutral collision spacing and outward velocity.
- **Commit Separation Multiplier**: applies a fraction of body separation during parry, launch, dunk, or special commitment. Zero preserves current behavior. Large values can hold fighters outside hit range and suppress combat, so change this independently.
- **Defense Reset Distance / Impulse**: applies bilateral displacement after a successful parry and provides the base reset used by launch break.
- **Launch Break Reset Scale**: scales the defense reset only for launch break. This keeps a limited escape resource independently tunable from repeatable parry defense.
- **Natural Recovery Reset Scale**: applies a fraction of the defense reset only when a launched fighter naturally regains control inside that scaled distance with at least 20% fuel remaining. The result is multiplied by that fighter package's **Natural Recovery Reset Multiplier**, allowing future classes to have distinct recovery identities without branching simulation code. It does not fire after a launch break, at low reserve, or once safe spacing already exists. Simultaneous returns resolve one symmetric reset after both fighters update, avoiding player-order bias. Zero preserves the current live mechanic.

The current defaults use `0.995` launch damping plus a 26-unit, 14-impulse defensive reset; launch breaks scale that reset by `1.1`. Launch clashes retain the previous 11.2-unit separation padding and `0.58` recoil scale as explicit controls rather than hard-coded values. A stronger `0.78` recoil candidate was rejected after a 12-set-per-direction mirrored comparison increased timeout share in three of four directions without consistently improving Chase, so no live mechanic changed.

Commit-separation candidates at `0.25` and `0.50` reduced contact in some fixed-seed directions but made reset conversion and timeout behavior worse, so the live value remains `0`. Action Recovery Control was then added to isolate the underlying question: whether held movement or boost is immediately erasing clash and defense recoil during move end lag. Its default of `1` reproduced the prior fixed-seed flow report with zero gameplay deltas. Candidates at `0.60` and `0.35` produced mixed direction-dependent pressure, reset, and timeout changes, so neither was promoted. The control remains available for deliberate manual experiments rather than becoming an inferred balance fix.

Launch Release Speed Ratio candidates at `0.45` and `0.50` were also rejected against a fresh current-code, mirrored four-direction screen. Individual helpless windows sometimes shortened, but received launches increased by as much as `3.8` per round, total helpless share often rose, and timeout share increased by roughly `30-85` percentage points. The default remains `0.38`. This result separates the mechanics question correctly: the current issue is repeated re-engagement and launch frequency after control returns, not simply an excessive per-hit helpless timer.

Natural Recovery Reset Scale candidates at `0.35`, `0.45`, and `0.55` were screened on the same 12-set-per-direction Veteran seeds. The telemetry now classifies pressure from `controlReturnStartDistance`, captured before same-frame reset displacement, so a candidate cannot remove its own qualifying events from the denominator. `0.35` improved generic reset conversion by `5.0` points but increased immediate re-launch by `11.5` points for one character side, reduced first-action reset conversion by up to `8.1` points, and moved Chase from `6` to `8` Blocked samples. `0.45` improved generic reset conversion by `5.1` points and reduced Blocked Chase samples to `4`, but every reached Chase sample remained flagged, sustained control-return reset fell by up to `10.0` points, first-action reset fell by up to `8.5` points, and resolved exchanges fell by `2.7` points. `0.55` reduced Chase to `4` Blocked samples and improved some control-return windows, but added a `3.33`-point timeout share, lengthened average rounds by `4.69s`, reduced overall reset conversion by `3.9` points, and reduced launch-break reset conversion by `9.9` points. None was promoted. The shipped default remains `0`, and the control plus Post-control agency probe remain available for visual, human-led iteration.

A later Cadet/Veteran v8 screen tested the Chase transition without using class set wins as a target. The older all-action recovery spacing policy and a blanket eight-frame spacing value both lowered immediate re-launch while reducing durable reset quality and eliminating qualified Vanguard finish completion. The replacement **Post-Control Steering** control retained valid tactical responses and suppressed only Duelist's inward auto-target dash during the window, but an eight-frame candidate still reduced exchange-reset quality and failed the finish-completion gate. Natural-reset candidates at `0.25` and `0.50`, including the reserve-aware rule, also reduced some Blocked Chase samples without creating enough sustained resets and failed qualified finish completion. Every live value remains unchanged; the controls are retained because they isolate the mechanics for human review without presenting a lower flag count as success.

A fresh v9 recovery screen used 12 Veteran sets in both Vanguard/Duelist directions on identical seeds. Raising **Natural Recovery Reset Scale** to `0.75` reduced Chase severity from `10 Blocked / 40 Watch` to `4 Blocked / 46 Watch` and the fixed human probe proves that the reset can preserve an actionable window against the same committed chase. It also added two Blocked Separation rounds and four Commitment Watch rounds, so it remains a candidate rather than a shipped default. A global two-frame **Startup Clash Grace** fixed one representative simultaneous counter-launch but converted Exchange into the dominant failure with roughly 40 Blocked rounds per mirrored pairing. Adding 12 frames of post-clash AI spacing made that loop worse, reaching 45 Blocked Exchange rounds per pairing. Those clash candidates were rejected; the live clash rule remains unchanged.

The v10 observability pass separates spacing from actual agency. **Shared movement control** requires neither fighter to be helpless, stunned, or in forced dunk recovery. **Shared action-ready time** is the stricter subset where neither fighter is also in end lag, parry, or an active launch, dunk, or special commitment. A **shared decision window** additionally requires both action-ready fighters to remain outside pressure for at least `0.75s`. The current four-game mirrored Cadet/Veteran local sample showed why this distinction matters: Cadet rounds had shared movement control for `18.7%` of sampled frames but shared action-ready time for only `5.0%` of frames (`26.8%` of shared control); Veteran measured `19.8%`, `3.8%`, and `19.1%`. While both could steer, the fighters remained in pressure for `81.5%` Cadet and `85.2%` Veteran, with physical contact at `14.9%` and `16.0%`. Only `0.33` Cadet and `0.10` Veteran shared decision windows occurred per round. This is evidence of chase and commitment saturation, not a class win-rate result, and no live mechanic changed. The next candidate should improve decision cadence while preserving accepted kit variety, exchange resolution, and finish progression; increasing collision impulse alone cannot address time spent helpless or committed.

The old Post-Control Guard Chance candidates at `0.25` and `0.50` were rejected because an immediate anticipatory parry was not a substitute for threat-aware defense or actual separation. The v4 replacement separates a disadvantage window, a block-special choice, and threat-confirmed parry. After correcting P1/P2 execution-order bias, a matched 12-frame / `0.50` block / `1.00` threat-parry candidate raised pressure and contact, reduced neutral resets by `1.35` per round, raised brief exits by `2.57` percentage points, and reduced Vanguard's sustained control-return reset conversion by `15.1` points. All three defaults remain `0`.

Editing a control stages an offline draft only; it does not silently change arcade, versus, online, or ranked rules.

Global and character drafts are selected only for offline Training, AI-vs-AI, and Balance Sparring match creation. Online, Arcade, and ordinary sparring matches always use configured global tuning and receive an empty character override map. Character overrides are part of deterministic game state, snapshots, rollback checksums, replay verification, and telemetry identity.

AI behavior drafts are selected only for local AI-vs-AI and Balance Sparring. In Balance Sparring they control only P2 while P1 remains human. They generate ordinary deterministic frame inputs; online simulation and ranked proofs never consult the local AI editor.

Built-in presets remain source-controlled in `apps/game-web/content/balance/balanceProfiles.ts`. A local `gw.balance-lab-draft.v3` payload is stored under `gravity_well.balance_lab.draft.v3` in browser storage and is never uploaded automatically. Version 1 tuning-only and version 2 global/character drafts are migrated with neutral AI behavior on load.

A fixed-seed eight-set-per-direction screen demonstrates why these controls are decision aids rather than an optimizer. Doubling only Engagement Distance Scale reduced physical contact from `11.18%` to `4.14%`, but raised pressure occupancy to `82.56%`, cut reset success from `54.60%` to `29.30%`, and produced `153/160` timed-out rounds. It was rejected. A standalone 18-frame Pressure-Exit Hold kept pressure and finishes near baseline while reset success moved to `57.25%`; the effect was too small and direction-dependent to promote.

A second matched screen used eight games per directed pairing across cadet and veteran. Baseline contact/pressure were `11.1%`/`55.9%`. Reducing only Neutral Inward Drive Scale to `0.5` moved them to `9.7%`/`60.6%` and introduced a `2.8%` timeout share; stronger and combined inward-drive candidates kept pressure at `60.6-61.5%` and created longer special-heavy exchanges, so they were rejected. Leaving inward drive at `1` and setting only Neutral Boost Distance Offset to `16` produced `9.9%` contact, `55.3%` pressure, no timeouts, and `215.1` accepted combat starts per minute versus `224.0` at baseline. That candidate remains available for human visual/play review, but no default changed: lower contact and cadence are not accepted without a visibly better neutral-to-finish loop.

Commitment candidates were then screened locally with fixed seeds. Independent timers drove pressure occupancy as high as `75-92%`, repeated specials, and widespread timeouts or draws. A later complementary-role implementation made both controllers agree on one initiative owner and stopped Guard or movement dash from being treated as an offensive whiff. A matched 24-frame response, 18-frame initiative, and 36-frame reset candidate still raised timeout share from `36.0%` to `88.3%`, pressure from `56.4%` to `73.5%`, and special resolutions from `24.7` to `42.6` per round; reset conversion fell from `63.2%` to `20.1%`. Its lower immediate re-launch rate was therefore rejected as a misleading isolated improvement. The three controls remain zero-default tools for manual iteration, and class win percentage was not used to decide the result.

The `flow-v15` follow-up corrected the experiment itself before drawing another conclusion: reset frames now count only shared action-ready frames, control returns and clashes can start the reset, and ordinary whiffs transfer initiative without forcing both fighters to disengage. Fixed-seed one-variable screens of `12`, `24`, and `48` reset frames and a `12`-frame observe-only window were all rejected. The 48-frame reset reduced Blocked Chase samples from `10` to `2`, but expanded the sample from `44` to `74` rounds, produced widespread draws/timeouts, added Separation failures, and weakened exchange-reset evidence. The observe-only screen expanded to `75` rounds and moved Separation from `2 Blocked / 4 Watch` to `21 Blocked / 29 Watch`, with timeout deltas of roughly `28-70` percentage points by profile. No live default changed. A future candidate must target a specific post-control recommit rather than imposing a broad pause or retreat cycle.

`flow-v16` added that narrower **Opponent Recovery Respect Frames** experiment without changing its zero default. The attacker observes only after the opponent regains control, can still defend, and uses a mild orbit rather than a forced global retreat. On 12 matched Veteran sets per direction, the zero baseline reported Commitment/Separation/Chase issue ratios of `92% / 20% / 100%`. The `12`, `18`, and `24` frame candidates reported `100% / 34.6% / 100%`, `100% / 36% / 92%`, and `87.5% / 33.3% / 95.8%`. Twelve and eighteen frames lengthened average sets by roughly nine to ten seconds; twenty-four stayed near baseline duration but created six Blocked Separation rounds. All three were rejected. The control remains useful for manual diagnosis, but attacker hesitation alone does not create the durable reset the game needs.

The retained finish-path pass used the same flow-first rule. Finish Pursuit Reach Scale `0.70` converted four exact previously missed Cadet/Veteran replay cases and lowered matched timeout share without materially moving contact or pressure. Vanguard package startup-pursuit candidates `62` and `66` were rejected because they created finish starts but no completed Vanguard finishes; package `0.3.2` at `70` completed the path in both difficulties. Threshold schema v8 retains the four-start qualification before enforcing a 20% finish-completion floor and now rejects qualified Commitment or Chase saturation. This is a move-funnel and loop-quality check, not a class or set win-rate target.

Experiment exports are also browser-local downloads and never touch the API or Neon. A bundle marked `invalid` records why the samples cannot be compared; `provisional` means the durations differ by more than 25% or baseline and candidate still refer to the same active run; `comparable` requires independent samples plus matching scenario, character packages, and duration controls. None of those labels score whether a class is strong or whether the match is fun.

## Flow-first acceptance order

Review candidates in this order:

1. Confirm identical seeds, pairings, AI profiles, packages, round cap, and fixed timestep.
2. Reject contact lock using the physical-contact share first, then point-blank share, pressure share, average pressure sequence, p90 pressure sequence, and the timeline.
3. Confirm exchanges create readable neutral using clash, parry, launch-break, and launch-defense success-to-reset conversion plus neutral-window duration. Separate whether the defender read the commitment, whether the chosen parry/guard/counter succeeded, and whether that success created a durable decision window. For clashes, also inspect recurrence, first accepted action, decision delay, and rapid launch recommit. For every pressure exit, separate deliberate first actions from carried brief re-entry. A high transition count or a longer pause without sustained windows is not a reset.
4. Confirm both agents still use a broad accepted kit and are not cycling one action or submitting mostly rejected inputs. Inspect accepted/requested counts per action and accepted combat starts per minute; a lower total cadence is not an improvement if launch attempts were merely replaced by specials inside the same pressure sequence. A low special ratio is an AI state-awareness problem until proven otherwise, not evidence that special damage or fuel cost needs a buff.
5. Confirm launch, chase, dunk, and zero-fuel finish sequences still happen. Reject a candidate that improves spacing by preventing attacks from connecting.
6. Reject a material timeout or finish-cadence regression even when spacing improves. More neutral is not useful if rounds stop progressing.
7. Use class win rate only after the loop passes. At this stage it is evidence of AI/kit asymmetry to inspect, not the optimization target.

Change one mechanic family at a time, first with both matchup directions and at least two AI profiles. Keep candidate JSON and reports as evidence, but do not promote a local draft into a built-in profile until the broad comparison and a human playtest agree.
